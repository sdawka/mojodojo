# Tile v2: Wishbone slave interface (register and memory map)

Status: **contract v2.0** (rev 1: run time includes one tail cycle, see section 6). The RTL (`tile2/rtl/tile2_n8.v`, generated by `rtlgen/tile2.mojo`) and the Mojo bus-level model (`systolic/tile2.mojo`) both implement this file, and the Verilator co-simulation checks them against each other. If something here disagrees with the RTL, that is a bug; tell lane-tile2.

## 1. What the block is

- An N×N int8 output-stationary systolic tile (the v1 core from `../DESIGN.md`, with a registered product stage added for fmax). N is a build-time constant; the default build is **N = 8** (64 MULT18X18D).
- Three on-chip operand/result buffers in block RAM: **A** (int8), **B** (int8), **C** (int32).
- A sequencer that computes `C[M×N] (=|+=) A[M×K] · B[K×N]` entirely from the buffers. Operands are int8, accumulation and results are int32 with two's-complement wraparound.
- One **Wishbone B4 classic, 32-bit, word-addressed** slave port (the LiteX `wishbone.Interface(data_width=32)` shape), plus one level `irq` output.

Firmware loads A and B into the buffers, writes the shape and layout registers, writes START, then polls STATUS (or waits for `irq`) and reads C back.

## 2. Ports (Verilog module `tile2_n8`)

| Port | Dir | Width | Meaning |
| --- | --- | --- | --- |
| `clk` | in | 1 | single clock, rising edge (the SoC `sys` clock) |
| `rst` | in | 1 | synchronous, active high. Resets every register (buffer contents are *not* cleared) |
| `wb_cyc` | in | 1 | Wishbone CYC |
| `wb_stb` | in | 1 | Wishbone STB |
| `wb_we` | in | 1 | Wishbone WE |
| `wb_adr` | in | 15 | **word** address inside the 128 KiB window (byte address `>> 2`). LiteX: connect `bus.adr[14:0]` |
| `wb_dat_w` | in | 32 | write data |
| `wb_sel` | in | 4 | byte lane enables (`sel[0]` = bits 7:0 = lowest byte address). Honoured on buffer writes; CSR writes ignore `sel` |
| `wb_dat_r` | out | 32 | read data, valid while `wb_ack` is high |
| `wb_ack` | out | 1 | Wishbone ACK |
| `irq` | out | 1 | `STATUS.DONE && MODE.IRQ_EN` (level) |

No `err`, `stall`, `cti` or `bte` ports: tie `err` to 0 on the LiteX side; CTI/BTE are ignored, so every access is terminated as a classic cycle (legal for incrementing bursts too).

**Timing.** ACK is registered: a request presented in cycle *t* (`cyc && stb && !ack`) is acknowledged in cycle *t+1*, and `wb_dat_r` is valid in that same cycle. Every access therefore takes exactly 2 cycles, there are no wait states, and the slave never stalls the bus (not even while busy). A write takes effect at the clock edge that ends cycle *t*.

## 3. Address map (byte offsets from the window base; window = 128 KiB = 0x20000)

| Offset | Size | Region | Access |
| --- | --- | --- | --- |
| `0x00000` | 32 KiB slot | CSRs (16 words, **aliased** every 64 B through the slot) | see §4 |
| `0x08000` | 16 KiB (slot 32 KiB, aliased) | **A buffer**, int8, byte addressable | R/W while not BUSY |
| `0x10000` | 32 KiB | **B buffer**, int8, byte addressable | R/W while not BUSY |
| `0x18000` | 32 KiB | **C buffer**, int32 (8192 words) | R/W while not BUSY |

The region is selected by byte-address bits [16:15] (`wb_adr[14:13]`). Inside a region, address bits above the buffer size are ignored (aliasing). Buffer sizes are build parameters; read `INFO` to discover them.

Buffers are little-endian like the RISC-V core: byte offset `4w+b` is lane `sel[b]` / bits `8b+7:8b` of word `w`. Byte (`sb`), half-word and word stores all work. Power-up contents are zero (ECP5 EBR init; Verilator zero-init); `rst` does not clear them.

**Buffer access while BUSY** (any region other than CSR reads): writes are dropped, reads return 0, and the access still ACKs in one cycle; the sticky `STATUS.ERR_BUSY` bit is set. The sequencer owns the buffer ports during a run.

## 4. CSRs (32-bit words, byte offsets inside the CSR slot)

| Off | Name | Access | Bits |
| --- | --- | --- | --- |
| `0x00` | `ID` | RO | `0x54494C32` ("TIL2") |
| `0x04` | `INFO` | RO | `[7:0]` N, `[15:8]` log2(A bytes), `[23:16]` log2(B bytes), `[31:24]` log2(C bytes). Default build: `0x0F0F0E08` |
| `0x08` | `CTRL` | WO (reads 0) | bit0 `START`, bit1 `CLEAR` (clears DONE, ERR_CFG, ERR_BUSY). Both are pulses; CLEAR is applied before START in the same write |
| `0x0C` | `STATUS` | RO | bit0 `BUSY`, bit1 `DONE` (sticky), bit2 `ERR_CFG` (sticky), bit3 `ERR_BUSY` (sticky) |
| `0x10` | `MODE` | RW `[1:0]` | bit0 `ACCUM` (C += A·B instead of C = A·B), bit1 `IRQ_EN` |
| `0x14` | `M` | RW `[15:0]` | rows of A / C, 1..65535 |
| `0x18` | `K` | RW `[15:0]` | reduction length, 1..65535 |
| `0x1C` | `N` | RW `[15:0]` | columns of B / C, 1..65535 |
| `0x20` | `A_BASE` | RW | byte offset of Aᵀ[0][0] in the A buffer. Multiple of N |
| `0x24` | `A_LD` | RW | byte stride between Aᵀ rows (consecutive k). Multiple of N |
| `0x28` | `B_BASE` | RW | byte offset of B[0][0] in the B buffer. Multiple of N |
| `0x2C` | `B_LD` | RW | byte stride between B rows. Multiple of N |
| `0x30` | `C_BASE` | RW | byte offset of C[0][0] in the C buffer. Multiple of 4N |
| `0x34` | `C_LD` | RW | byte stride between C rows. Multiple of 4N |
| `0x38` | `CYCLES` | RO | busy cycles of the current/last run (cleared by an accepted START) |
| `0x3C` | — | RO | reads 0 |

Register write rules:
- Address/stride registers keep only the bits that matter: `A_BASE`, `A_LD` keep bits `[log2(A bytes)-1 : log2 N]`, likewise B; `C_BASE`, `C_LD` keep `[log2(C bytes)-1 : log2(4N)]`. Other bits are dropped and read back as 0. (Default build: A bits [13:3], B [14:3], C [14:5].)
- `M`, `K`, `N` keep bits [15:0]; `MODE` keeps [1:0].
- Writes to RO registers are ignored. CSR writes ignore `wb_sel`; use word stores.
- **Any write while BUSY** (CSR or buffer, including CTRL) is ignored and sets `ERR_BUSY`. CSR reads while BUSY are fine (that is how you poll).
- START with `M == 0 || K == 0 || N == 0` is rejected: nothing runs and `ERR_CFG` is set. An accepted START clears `DONE` and `CYCLES`, sets `BUSY`. Errors are cleared only by `CLEAR` or `rst`.

## 5. Data layout in the buffers

The tile consumes one column of A and one row of B per cycle, so **both operands are stored with k as the row index**:

```
A buffer:  byte  A_BASE + k*A_LD + m      = A[m][k]      (i.e. Aᵀ, K rows of M bytes)   m < M, k < K
B buffer:  byte  B_BASE + k*B_LD + n      = B[k][n]      (plain row-major B)              n < N, k < K
C buffer:  word  C_BASE + m*C_LD + 4*n    = C[m][n]      (plain row-major C, int32)       m < M, n < N
```

Requirements: `A_LD ≥ roundup(M, Nt)`, `B_LD ≥ roundup(N, Nt)`, `C_LD ≥ 4*roundup(N, Nt)` (Nt = tile size from INFO, default 8), all with the alignments of §4. The hardware reads whole Nt-wide groups, so the padding bytes between `M` and `roundup(M, Nt)` in each Aᵀ row (and between N and `roundup(N, Nt)` in each B row) are *read*, but **their contents never matter**: PE(i,j) only combines Aᵀ lane i with B lane j, so padding lanes only reach padded outputs, which are never written. In C, only the `M×N` elements are written; padding words and rows ≥ M are left untouched. All address arithmetic wraps modulo the buffer size.

Overlapping C tiles (C_LD too small) or overlapping A/B within a buffer is the firmware's problem; results are then defined only by the hardware's write order (tile order below).

## 6. Execution and timing

The sequencer visits output tiles row-major: `tm = 0..ceil(M/Nt)-1` outer, `tn = 0..ceil(N/Nt)-1` inner, and runs one full-K pass of the core per tile, back to back. With `ACCUM=1`, each C row is read and the new sum written in the same drain cycle (so K can be split across runs: run 1 with ACCUM=0, later runs with ACCUM=1 and shifted A_BASE/B_BASE).

Exact busy time (this is what `CYCLES` reads after DONE; the RTL and the Mojo model agree cycle-for-cycle):

```
CYCLES = 2 + ceil(M/Nt) * ceil(N/Nt) * (K + 3*Nt)          (Nt = 8: K + 24 per tile)
         ^ 1 setup cycle (first operand fetch) + 1 tail cycle (last, pipelined C write)
per tile: 1 start + K feed + (2Nt-1) flush + Nt drain
```

`BUSY` is high from the cycle after the START write's request cycle for exactly `CYCLES` cycles; `DONE` (and `irq` if enabled) rise as `BUSY` falls. PE utilisation per pass is `K / (K + 3Nt)`: 97.7% at K=1024, Nt=8.

## 7. Programming sequence (firmware)

```
base = <window base>
assert rd(base+0x00) == 0x54494C32                 # ID
info = rd(base+0x04); Nt = info & 0xFF
wait until (rd(base+0x0C) & BUSY) == 0

# 1. operands (any store width; only while not BUSY)
for k < K, m < M:  wr8 (base+0x08000 + A_BASE + k*A_LD + m, A[m][k])
for k < K, n < N:  wr8 (base+0x10000 + B_BASE + k*B_LD + n, B[k][n])
# (with ACCUM=1, also preload C[m][n] at base+0x18000 + C_BASE + m*C_LD + 4n)

# 2. shape / layout / mode
wr32(base+0x14, M); wr32(base+0x18, K); wr32(base+0x1C, N)
wr32(base+0x20, A_BASE); wr32(base+0x24, A_LD)
wr32(base+0x28, B_BASE); wr32(base+0x2C, B_LD)
wr32(base+0x30, C_BASE); wr32(base+0x34, C_LD)
wr32(base+0x10, ACCUM | IRQ_EN<<1)

# 3. run
wr32(base+0x08, 0b11)                               # CLEAR | START
while rd(base+0x0C) & BUSY: pass                    # or wait for irq
st = rd(base+0x0C); assert st & DONE and not (st & 0b1100)

# 4. results
C[m][n] = (int32) rd32(base+0x18000 + C_BASE + m*C_LD + 4n)
cycles  = rd32(base+0x38)
wr32(base+0x08, 0b10)                               # CLEAR (drops DONE / irq)
```

Typical packing with defaults: Mt = roundup(M,8), Nr = roundup(N,8): `A_LD = Mt`, `B_LD = Nr`, `C_LD = 4*Nr`, all bases 0. Capacity: `K*Mt ≤ 16384`, `K*Nr ≤ 32768`, `M*Nr ≤ 8192`; e.g. M=8, K=1024, N=32 fits in one run.

## 8. LiteX integration notes

```python
tile = TileV2Wrapper(platform)            # instance of tile2_n8 via Instance("tile2_n8", ...)
self.bus.add_slave("tile2", tile.bus, region=SoCRegion(origin=0x9000_0000, size=0x20000, cached=False))
# Instance ports: i_wb_adr=bus.adr[:15], i_wb_dat_w=bus.dat_w, o_wb_dat_r=bus.dat_r,
#   i_wb_sel=bus.sel, i_wb_cyc=bus.cyc, i_wb_stb=bus.stb, i_wb_we=bus.we, o_wb_ack=bus.ack,
#   i_clk=ClockSignal("sys"), i_rst=ResetSignal("sys"), o_irq=<irq line>
```

Map the region **uncached** (`cached=False`, i.e. an IO region) so the CPU's data cache neither bursts into nor caches the buffers. The window must be 128 KiB-aligned so that `adr[14:0]` is the offset.
